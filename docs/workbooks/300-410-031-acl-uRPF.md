# ACL And uRPF

## Scope and prerequisites

Three IOL-XE routers form an intentionally asymmetric triangle. HOST service requests enter GW directly, while the explicit reverse host route returns through TRANSIT to the second HOST interface. Actual successful baseline traffic proves this is not a missing-return-route failure. Strict uRPF on the direct ingress must reject the loopback source and increment verification drops, while a source on the directly connected ingress subnet still works. Loose uRPF must recover the asymmetric source because its reverse route exists. A separate source-prefix ACL then rejects that same otherwise reachable source and counts actual denies. Removing the ACL and finally uRPF must restore the original path. This is an IPv4 CEF/source-validation exercise, not identity authentication or a claim that strict mode is appropriate for asymmetric production routing. Nominal RAM is3GiB.

Use licensed reference images for iol-xe in CML 2.10.1. All addresses are educational. No Internet, external connector or production credentials are required. Starting state: Working isolated reference baseline. Functional status and exact tested images: [results](../../validation/RESULTS.md).

## Topology and addressing

- HOST Ethernet0/0 <-> GW Ethernet0/0
- GW Ethernet0/1 <-> TRANSIT Ethernet0/0
- TRANSIT Ethernet0/1 <-> HOST Ethernet0/1

| Node | Interface | Address |
| --- | --- | --- |
| HOST | Loopback0 | `ip address 192.0.2.10 255.255.255.255` |
| HOST | Ethernet0/0 | `ip address 198.18.0.2 255.255.255.252` |
| HOST | Ethernet0/1 | `ip address 198.18.2.2 255.255.255.252` |
| GW | Ethernet0/0 | `ip address 198.18.0.1 255.255.255.252` |
| GW | Ethernet0/1 | `ip address 198.18.1.1 255.255.255.252` |
| GW | Loopback0 | `ip address 192.0.2.80 255.255.255.255` |
| TRANSIT | Ethernet0/0 | `ip address 198.18.1.2 255.255.255.252` |
| TRANSIT | Ethernet0/1 | `ip address 198.18.2.1 255.255.255.252` |

## Tasks

1. Prove an actually working asymmetric return path before applying source validation.
2. Compare strict versus loose uRPF with the reverse route still installed.
3. Separate a source-prefix ACL from RIB reachability and restore the original asymmetric baseline.

## Baseline acceptance

| Node | Command | Observable result |
| --- | --- | --- |
| GW | `show ip route 192.0.2.10` | The real reverse route deliberately points to the other interface. |
| HOST | `ping 192.0.2.80 source Loopback0 repeat 3` | The explicitly asymmetric service probe forwards. |
| HOST | `ping 192.0.2.80 source Ethernet0/0 repeat 3` | A source whose reverse path matches ingress remains healthy. |

## Transition: enable strict reverse-path validation

On **GW**:

```ios
configure terminal
interface Ethernet0/0
ip verify unicast source reachable-via rx
end
```

- HOST: `ping 192.0.2.80 source Loopback0 repeat 3` -- The explicitly asymmetric service probe is rejected by the selected source-validation control.
- GW: `show ip interface Ethernet0/0` -- The actual uRPF verifier counts rejected packets.
- HOST: `ping 192.0.2.80 source Ethernet0/0 repeat 3` -- A source whose reverse path matches ingress remains healthy.
- GW: `show ip route 192.0.2.10` -- The real reverse route deliberately points to the other interface.

## Transition: allow asymmetric reachable sources with loose mode

On **GW**:

```ios
configure terminal
interface Ethernet0/0
no ip verify unicast source reachable-via rx
ip verify unicast source reachable-via any
end
```

- HOST: `ping 192.0.2.80 source Loopback0 repeat 3` -- The explicitly asymmetric service probe forwards.
- HOST: `ping 192.0.2.80 source Ethernet0/0 repeat 3` -- A source whose reverse path matches ingress remains healthy.
- GW: `show ip route 192.0.2.10` -- The real reverse route deliberately points to the other interface.

## Transition: apply an independent source-prefix ACL

On **GW**:

```ios
configure terminal
ip access-list standard SOURCE-PREFIX
permit 198.18.0.0 0.0.0.3
deny any
exit
interface Ethernet0/0
ip access-group SOURCE-PREFIX in
end
```

- HOST: `ping 192.0.2.80 source Loopback0 repeat 3` -- The explicitly asymmetric service probe is rejected by the selected source-validation control.
- HOST: `ping 192.0.2.80 source Ethernet0/0 repeat 3` -- A source whose reverse path matches ingress remains healthy.
- GW: `show access-lists SOURCE-PREFIX` -- The independent prefix policy counts actual source denies.

## Transition: remove only the prefix policy

On **GW**:

```ios
configure terminal
interface Ethernet0/0
no ip access-group SOURCE-PREFIX in
end
```

- HOST: `ping 192.0.2.80 source Loopback0 repeat 3` -- The explicitly asymmetric service probe forwards.
- GW: `show ip route 192.0.2.10` -- The real reverse route deliberately points to the other interface.

## Transition: restore the original unfiltered asymmetric path

On **GW**:

```ios
configure terminal
interface Ethernet0/0
no ip verify unicast source reachable-via any
end
```

- HOST: `ping 192.0.2.80 source Loopback0 repeat 3` -- The explicitly asymmetric service probe forwards.
- HOST: `ping 192.0.2.80 source Ethernet0/0 repeat 3` -- A source whose reverse path matches ingress remains healthy.
- GW: `show ip route 192.0.2.10` -- The real reverse route deliberately points to the other interface.

## Reference configuration and recovery

The checked-in topology carries the reference configurations below. To reset a disposable exercise, stop and wipe only your imported copy, then restart or import the YAML again. Never apply the fault actions to a production device. Fault transitions restore the routing baseline; file-copy exercises may leave their documented output until wipe. Repeat the applicable acceptance checks before ending the exercise.

### HOST

```ios
hostname HOST
no ip domain-lookup
no service config
ip cef
line console 0
 exec-timeout 0 0
 logging synchronous
 exit
interface range Ethernet0/0 - 3
 no ip address
 shutdown
 exit
interface Loopback0
 ip address 192.0.2.10 255.255.255.255
 no shutdown
 exit
interface Ethernet0/0
 ip address 198.18.0.2 255.255.255.252
 no shutdown
 exit
interface Ethernet0/1
 ip address 198.18.2.2 255.255.255.252
 no shutdown
 exit
ip route 0.0.0.0 0.0.0.0 198.18.0.1
end
```
