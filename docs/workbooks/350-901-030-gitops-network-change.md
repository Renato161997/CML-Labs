# GitOps Network Change

## Scope and prerequisites

A real CSR1000v 17.3.8a and the open-source CML-Labs toolbox exchange NETCONF and RESTCONF over an isolated benchmark network. Nominal RAM is 3072+1024 MiB, with two router vCPUs. The registered iosxe-api-v1 preparation is implementation-digest-bound: it creates fresh RSA3072 keys and an explicit DNS-SAN certificate, sets only the disposable guest clock, waits for YANG daemons, exports public trust material over authenticated CML serial, matches ssh-keyscan against those serial-derived public keys, and checksum-verifies transfer to the client. No private key or CML administrator credential enters the guest client. TLS verification remains enabled, and NETCONF uses an explicit key pin plus a strict IOSXE ncclient handler: the stock ncclient0.6.17 IOSXE callback accepts unknown keys and is deliberately overridden. Wrong-password, wrong-hostname and wrong-key negative controls precede a fresh valid connection. All credentials in this file are public isolated training fixtures. This tested legacy CSR reference platform is an interoperability exercise, not a production cryptographic recommendation. No Internet, external connector or existing lab is used; stop/wipe only your imported copy to reset. The harness performs preparation automatically; its source scripts/iosxe_prepare.py also documents the serial steps and the known certificate-enrollment dialogue. Do not bypass verification if a certificate or key differs. Git actually runs in a local repository with real immutable commits; no GitHub server, CI provider or external account is contacted. The review decision is an explicit simulated training approval stored outside the proposed repository, not a claim of real human or provider-enforced approval. Deployment reads the approved commit object, never arbitrary working-tree content. An allowlist limits intent to one benchmark /32 route. NETCONF changes real device state and independent IOS-to-Linux ICMP verifies delivery. No unreviewed branch, default route or arbitrary CLI command may be applied. The root-owned isolated fixture is a teaching mechanism, not a production identity boundary. Files and rejected proposal branches remain in the disposable client until wipe.

Use licensed reference images for cml-labs-toolbox, csr1000v in CML 2.10.1. All addresses are educational. No Internet, external connector or production credentials are required. Starting state: Working isolated reference baseline. Functional status and exact tested images: [results](../../validation/RESULTS.md).

## Tasks

1. Create a real local Git commit and reconcile its explicitly approved route intent.
2. Detect actual device drift while the approved revision stays unchanged, then restore forwarding.
3. Prove state idempotence and, for the pipeline exercise, block unreviewed and out-of-policy proposals before device writes.

On **API**:


- API: `ping 192.0.2.42 repeat 3` -- Actual forwarding fails while the approved Git intent remains unchanged.
- API: `ping 198.18.0.2 repeat 3` -- Management remains available during destination-route drift.

## Transition: reconcile the immutable approved intent

On **TOOLS**:

```ios
python3 /lab/gitops_probe.py reconcile
```

- TOOLS: `python3 /lab/route_probe.py present` -- Independent NETCONF confirms the approved next hop.
- API: `ping 192.0.2.42 repeat 3` -- Actual forwarding reaches the Linux loopback.
- API: `ping 198.18.0.2 repeat 3` -- Management remains available during destination-route drift.
