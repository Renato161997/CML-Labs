# IPsec VTI

## Scope and prerequisites

Two IOSv routers use tunnel mode ipsec ipv4 with an IPsec profile, AES256/SHA256 and PFS14. Explicit service routes select the VTI; there is no crypto-map interesting-traffic ACL. Both peers must show actual encryption and decapsulation counters. An ingress ESP filter blocks only protected packets while unprotected peer reachability and IKE remain healthy. A separate service-route withdrawal must fail the loopback service while an actual tunnel-peer ping still succeeds. Restoring each fault must recover the same protected service. Nominal RAM is1GiB. IKEv1 and the public exercise-only PSK are legacy interoperability fixtures, not production authentication guidance. All peers and prefixes are isolated. This verifies software protocol and packet behavior, not hardware cryptographic throughput.

Use licensed reference images for iosv in CML 2.10.1. All addresses are educational. No Internet, external connector or production credentials are required. Starting state: Working isolated reference baseline. Functional status and exact tested images: [results](../../validation/RESULTS.md).

## Tasks

1. Verify a real route-based IPsec VTI and actual encrypted traffic in both directions.
2. Drop ESP while preserving underlay/IKE and prove protected traffic cannot bypass the tunnel.
3. Remove only the service route while the encrypted tunnel-peer path remains healthy.

## Baseline acceptance

| Node | Command | Observable result |
| --- | --- | --- |
| R1 | `ping 198.18.0.2 repeat 3` | The unprotected peer transport remains reachable. |
| R1 | `ping 192.0.2.2 source Loopback0 repeat 3` | The actual protected service loopback replies. |
| R1 | `show crypto isakmp sa` | The actual IKEv1 session reaches Quick Mode idle. |
| R1 | `show crypto ipsec sa | include #pkts|transform` | Both actual protected packet directions are nonzero with AES256/SHA256. |
| R2 | `show crypto ipsec sa | include #pkts|transform` | Both actual protected packet directions are nonzero with AES256/SHA256. |
| R1 | `show interfaces Tunnel0` | The actual tunnel uses native IPsec rather than GRE. |

## Transition: drop only encrypted VTI payload

On **R2**:

```ios
configure terminal
ip access-list extended VTI-OUTER
deny esp any any
permit ip any any
exit
interface GigabitEthernet0/0
ip access-group VTI-OUTER in
end
```

- R1: `ping 192.0.2.2 source Loopback0 repeat 3` -- The controlled fault blocks the protected service.
- R1: `ping 198.18.0.2 repeat 3` -- The unprotected peer transport remains reachable.
- R1: `show crypto isakmp sa` -- The actual IKEv1 session reaches Quick Mode idle.
- R2: `show access-lists VTI-OUTER` -- The filter counts actual ESP drops.

## Transition: restore VTI ESP forwarding

On **R2**:

```ios
configure terminal
interface GigabitEthernet0/0
no ip access-group VTI-OUTER in
end
```

- R1: `ping 192.0.2.2 source Loopback0 repeat 3` -- The actual protected service loopback replies.
- R1: `show crypto ipsec sa | include #pkts|transform` -- Both actual protected packet directions are nonzero with AES256/SHA256.
- R2: `show crypto ipsec sa | include #pkts|transform` -- Both actual protected packet directions are nonzero with AES256/SHA256.

## Transition: withdraw only the protected service route

On **R1**:

```ios
configure terminal
no ip route 192.0.2.2 255.255.255.255 Tunnel0
end
```

- R1: `ping 192.0.2.2 source Loopback0 repeat 3` -- The controlled fault blocks the protected service.
- R1: `ping 172.16.0.2 source Tunnel0 repeat 3` -- The encrypted tunnel-peer path remains healthy.
- R1: `ping 198.18.0.2 repeat 3` -- The unprotected peer transport remains reachable.

## Transition: restore the service route through VTI

On **R1**:

```ios
configure terminal
ip route 192.0.2.2 255.255.255.255 Tunnel0
end
```

- R1: `ping 192.0.2.2 source Loopback0 repeat 3` -- The actual protected service loopback replies.
- R1: `show crypto ipsec sa | include #pkts|transform` -- Both actual protected packet directions are nonzero with AES256/SHA256.
- R2: `show crypto ipsec sa | include #pkts|transform` -- Both actual protected packet directions are nonzero with AES256/SHA256.

## Reference configuration and recovery

The checked-in topology carries the reference configurations below. To reset a disposable exercise, stop and wipe only your imported copy, then restart or import the YAML again. Never apply the fault actions to a production device. Fault transitions restore the routing baseline; file-copy exercises may leave their documented output until wipe. Repeat the applicable acceptance checks before ending the exercise.

### R1

```ios
hostname R1
no ip domain-lookup
no service config
ip cef
line console 0
 exec-timeout 0 0
 logging synchronous
 exit
no logging console
crypto isakmp policy 10
 encryption aes 256
 hash sha256
 authentication pre-share
 group 14
 lifetime 3600
 exit
crypto isakmp key CML-VPN-DESIGN-PUBLIC-ONLY address 198.18.0.2
crypto ipsec transform-set DESIGN-SET esp-aes 256 esp-sha256-hmac
 mode tunnel
 exit
crypto ipsec profile DESIGN-PROFILE
 set transform-set DESIGN-SET
 set pfs group14
 exit
interface Loopback0
 ip address 192.0.2.1 255.255.255.255
 no shutdown
 exit
interface GigabitEthernet0/0
 ip address 198.18.0.1 255.255.255.252
 no shutdown
 exit
interface Tunnel0
 ip address 172.16.0.1 255.255.255.252
 ip mtu 1400
 tunnel source GigabitEthernet0/0
 tunnel destination 198.18.0.2
 tunnel mode ipsec ipv4
 tunnel protection ipsec profile DESIGN-PROFILE
 no shutdown
 exit
ip route 192.0.2.2 255.255.255.255 Tunnel0
end
```
