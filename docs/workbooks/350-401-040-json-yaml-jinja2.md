# JSON YAML Jinja2

## Scope and prerequisites

A real CSR1000v 17.3.8a and the open-source CML-Labs toolbox exchange NETCONF and RESTCONF over an isolated benchmark network. Nominal RAM is 3072+1024 MiB, with two router vCPUs. The registered iosxe-api-v1 preparation is implementation-digest-bound: it creates fresh RSA3072 keys and an explicit DNS-SAN certificate, sets only the disposable guest clock, waits for YANG daemons, exports public trust material over authenticated CML serial, matches ssh-keyscan against those serial-derived public keys, and checksum-verifies transfer to the client. No private key or CML administrator credential enters the guest client. TLS verification remains enabled, and NETCONF uses an explicit key pin plus a strict IOSXE ncclient handler: the stock ncclient0.6.17 IOSXE callback accepts unknown keys and is deliberately overridden. Wrong-password, wrong-hostname and wrong-key negative controls precede a fresh valid connection. All credentials in this file are public isolated training fixtures. This tested legacy CSR reference platform is an interoperability exercise, not a production cryptographic recommendation. No Internet, external connector or existing lab is used; stop/wipe only your imported copy to reset. The harness performs preparation automatically; its source scripts/iosxe_prepare.py also documents the serial steps and the known certificate-enrollment dialogue. Do not bypass verification if a certificate or key differs. Jinja2 actually runs inside the open-source toolbox. Rendering is configuration generation only: the rendered file is not applied and no deployment is claimed. The real device is read before and after to establish that boundary.

Use licensed reference images for cml-labs-toolbox, csr1000v in CML 2.10.1. All addresses are educational. No Internet, external connector or production credentials are required. Starting state: Working isolated reference baseline. Functional status and exact tested images: [results](../../validation/RESULTS.md).
