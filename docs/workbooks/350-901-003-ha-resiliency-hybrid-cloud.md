# HA Resiliency Hybrid Cloud

## Scope and prerequisites

Four native Linux guests and an IOL-L2 XE access switch form an actual frontend and two backend applications on separate links. Every accepted response contains data read from a real remote backend and the selected upstream identity; frontend health is distinct from application availability. The frontend performs round-robin selection and at most two bounded connection attempts. Faults stop only the disposable application PID, never an existing guest or controller. Read-only resource responses are stateless and identical: no shared database, session replication, geographical failure domain, hybrid-cloud deployment or frontend redundancy is claimed. The HA case deliberately exposes the frontend as a remaining single point of failure. These are local executable demonstrations of application separation, planned replica scale-in and backend resilience, not vendor integration or a throughput benchmark. All Python sources are inspectable and embedded; the control header is a public training fixture and the whole topology is isolated plaintext HTTP. No Internet, credentials or external connector is needed.

Use licensed reference images for ioll2-xe, net-tools in CML 2.10.1. All addresses are educational. No Internet, external connector or production credentials are required. Starting state: Working isolated reference baseline. Functional status and exact tested images: [results](../../validation/RESULTS.md).

## Tasks

1. Observe successful reads while both backend replicas are available.
2. Stop one backend and prove successful fallback without treating frontend liveness as readiness.
3. Stop both backends, require bounded HTTP503 failure, and restore service in two stages.

## Reference configuration and recovery

The checked-in topology carries the reference configurations below. To reset a disposable exercise, stop and wipe only your imported copy, then restart or import the YAML again. Never apply the fault actions to a production device. Fault transitions restore the routing baseline; file-copy exercises may leave their documented output until wipe. Repeat the applicable acceptance checks before ending the exercise.
