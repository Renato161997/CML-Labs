# NAC Concepts: Certificate Identity and Weaker MAC Fallback

## Scope and prerequisites

AUTH and CLIENT are actual native protocol-services guests running hostapd and wpa_supplicant with the wired driver and EAP-TLS. Each generates its own fresh RSA key/self-signed certificate inside the imported copy; no private key leaves its guest or is embedded in Git. Root-owned key files must be mode 0600. A separate closed bootstrap link exchanges only public peer certificates, which are checked for their explicit fixture name, self-signature and current validity before use. This unauthenticated teaching bootstrap is not a secure enrollment protocol or an organization PKI. The fixed client certificate/key and pinned server name are exercised by the actual EAP/TLS implementations, not a mocked authorization flag.

The data path is CLIENT eth1 -> AUTH eth1/br0/eth2 -> SERVER eth1. AUTH eth3 and CLIENT eth2 form only the certificate/control subnet. AUTH installs an explicit unreachable route for the data subnet, so that control path is not a routed alternative to SERVER. The three-node exercise has no Internet connector. CLIENT's actual EAP success and three ICMP replies establish the authenticated baseline; the SERVER's local HTTP listener remains an independent positive control throughout.

AUTH uses a real Linux bridge locked ingress port with learning disabled and link-local learning suppressed. After the temporary control-path host route is removed, authorized data must produce two consecutive complete three-packet trains within a bounded recovery window; incomplete output, persistent loss and late recovery fail. This allows measured route/neighbor convergence without treating one successful packet as recovery. Its root admission worker reads the actual hostapd authorized-station flag and refreshes only the fixed client MAC as a dynamic bridge FDB entry. An independent kernel JSON read must show the lock/learning settings and actual admission entry. The short FDB lease is tested by stopping only that worker: the entry must age out and client-originated packets must fail even though actual EAP authentication remains successful. Restarting a different worker PID must recover packets using the still authenticated peer. This is bounded ingress admission, not bidirectional confidentiality, MACsec, anti-spoofing on a shared physical segment or a production NAC product.

Changing only the client's exact expected server name must produce an observed EAP certificate-domain mismatch, no successful EAP state, no strict admission entry and zero of three data packets, while the separate certificate/control path and local SERVER service stay healthy. A deliberate root-only local MAC-whitelist mode then admits that same MAC despite the failed certificate check; packets must actually recover. This demonstrates the weaker identity assurance of MAC-only fallback. It is not Cisco MAB, a RADIUS exchange, ISE, dynamic VLAN assignment or a general certificate policy. Restoring strict mode must block that peer again, and restoring its correct name must recover real EAP-TLS and data.

The wired test follows the [upstream hostapd/supplicant setup](https://kernel.googlesource.com/pub/scm/network/wireless/iwd/+/master/doc/8021x-wired-testing.txt) with TLS client certificates rather than its password example. The [Linux bridge documentation](https://kernel.org/doc/html/latest/networking/bridge.html) describes locked-port and link-local learning semantics. Only the explicitly measured implementation/kernel profile is claimed; all processes, keys and state disappear when the disposable copy is wiped.


Use licensed reference images for cml-labs-services, net-tools in CML 2.10.1. All addresses are educational. No Internet, external connector or production credentials are required. ## Tasks

1. Observe actual wired EAP-TLS peer authentication and independently measured packet admission.
2. Reject the wrong certificate identity, and distinguish strict admission from weaker local MAC fallback.
3. Expire a stopped admission worker lease, preserve service controls and recover authenticated data.

## Reference configuration and recovery

The checked-in topology carries the reference configurations below. To reset a disposable exercise, stop and wipe only your imported copy, then restart or import the YAML again. Never apply the fault actions to a production device. Fault transitions restore the routing baseline; file-copy exercises may leave their documented output until wipe. Repeat the applicable acceptance checks before ending the exercise.
